Flujos principales

Secuencias convertibles en endpoints, servicios y pruebas.

Flujo A — Cargar mapa productivo

React solicita puntos productivos

MapPage envía filtros: territorio, cultivo, disponibilidad, cantidad mínima y zoom.

FastAPI valida parámetros

geo_router y production_router validan query params con schemas.

production_service consulta Supabase

Obtiene fincas, lotes de producción y agregaciones por zona.

Backend normaliza respuesta

Devuelve GeoJSON o JSON listo para Leaflet/MapLibre.

Frontend renderiza mapa y panel

El mapa pinta puntos; el panel muestra finca, cultivo, kg disponibles y contacto.


Flujo B — Comprador busca materia prima

Comprador define necesidad

Ejemplo: plátano, 800 kg, cerca de Buga, máximo 40 km.

marketplace_service busca oferta

Filtra por cultivo, disponibilidad, cantidad, territorio y distancia.

Sistema recomienda alternativas

Si una finca no alcanza la cantidad, combina o sugiere fincas cercanas.

Comprador revisa fichas

Ve foto, descripción, cantidad, disponibilidad, ubicación y contacto.

Se registra solicitud

buyer_requests guarda trazabilidad de intención comercial.


Flujo C — Pregunta al asistente IA

Usuario pregunta

“¿Dónde puedo conseguir 800 kg de plátano cerca de Buga?”

assistant_router arma contexto operativo

Zona activa, filtros, fincas visibles, disponibilidad y KPIs.

rag_service recupera contexto técnico

Documentos sobre clima, temporada, cultivo, suelo o datos públicos.

openrouter_service genera respuesta

El prompt exige no inventar oferta y diferenciar datos reales de recomendaciones.

Respuesta queda registrada

assistant_messages guarda pregunta, respuesta, zona y metadatos.

Decisiones de arquitectura

Reglas técnicas para mantener el proyecto entendible, mantenible y escalable.

Monolito modular

Un solo deploy para reducir complejidad operativa, pero con routers, services y schemas separados por dominio.

Backend como autoridad

El frontend no consulta Supabase ni OpenRouter directamente. El backend protege claves, valida y normaliza.

Datos propios primero

La caracterización de productores es la fuente principal. Las APIs públicas enriquecen y contextualizan.

IA con evidencia

El asistente usa datos del mapa, KPIs y RAG. No debe inventar disponibilidad, precios ni contactos.

Fallbacks obligatorios

Mapa, perfiles y filtros deben funcionar aunque fallen OpenRouter, RAG o APIs externas.

Escalabilidad progresiva

Primero mapa y producción; luego marketplace, ETL, RAG, IA, gamificación y AR.
